# Code signing and winget

Two things make FileWheel easier to install for everyone: a **code signature** (Windows SmartScreen stops warning "Windows protected your PC") and a **winget package** (`winget install FileWheel.FileWheel`). Both are prepared in the GitHub Actions workflow and switch on as soon as the corresponding secret exists. Until then, the build simply skips them.

## 1. Free code signing with SignPath Foundation

[SignPath Foundation](https://signpath.org) signs open-source projects for free, with a certificate issued to the foundation, as long as the binaries are built by a public CI from a public repository — which is exactly how FileWheel is built.

Steps for the repository owner:
1. Apply at <https://signpath.org/apply> with the repository URL (`https://github.com/nabeiroriviereadriano-design/FileWheel`), the MIT license and a short description. The project must be public, actively maintained and its builds reproducible from the repository (they are: `.github/workflows/build.yml`).
2. Once accepted, SignPath gives an **organization ID**, a **project slug**, a **signing policy slug** (usually `release-signing`) and lets you create an **API token** (CI user).
3. In GitHub: *Settings › Secrets and variables › Actions*:
   - **Secret** `SIGNPATH_API_TOKEN` = the API token;
   - **Variables** `SIGNPATH_ORGANIZATION_ID`, `SIGNPATH_PROJECT_SLUG`, `SIGNPATH_POLICY_SLUG`.
4. Install the SignPath GitHub App on the repository if SignPath asks for it (it checks that the artifacts really come from this workflow).

From then on, every build of `main`, of a tag or of a release signs `FileWheel.exe` (before packaging) and `FileWheel-Setup-<version>.exe` (after packaging). Pull requests are never signed.

Note: SmartScreen also builds a reputation over time; a signed installer gets it much faster than an unsigned one.

## 2. winget

Every build produces the manifests of the version (`winget-manifests-<version>.zip` in the release files): package `FileWheel.FileWheel`, NSIS installer, per-user scope, silent switch `/S`, SHA-256 of the installer, English and French descriptions. They are generated by `installer/New-WingetManifest.ps1`.

### First submission (once, by hand)

winget only accepts a new package through a pull request to [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs):
1. Publish a release (the installer must be downloadable from its final URL).
2. On a Windows PC: `winget install wingetcreate`, then
   `wingetcreate submit --token <a GitHub personal access token with "public_repo"> <folder of the extracted manifests>`
   (or open the pull request by hand with the 4 YAML files under `manifests/f/FileWheel/FileWheel/<version>/`).
3. Microsoft's validation runs automatically (installs and uninstalls the package in a sandbox); a moderator then merges it. After that, `winget install FileWheel.FileWheel` works for everyone.

### Following versions (automatic)

Add a **secret** `WINGET_TOKEN` (personal access token with `public_repo`, from the account that owns the fork of winget-pkgs). The workflow then runs `wingetcreate submit` for each published release.
